# 🤖 ถอดรหัสหรรษา 3D (Robot Code Adventure)

สื่อการสอนเกม 3 ภารกิจ พัฒนาจากใบงาน A4 มี 2 โหมด คือ **ใบงานต้นฉบับ** และ **ผจญภัยสุ่มโจทย์** ใช้งานได้กับคอมพิวเตอร์ แท็บเล็ต และโทรศัพท์ ผ่านเว็บไซต์ที่รองรับ JavaScript

## การเล่น

1. ภารกิจ 1 ถอดรหัส ⭐ 🔴 ❤️ → `2 1 3` ในโหมดใบงาน
2. ภารกิจ 2 ถอดรหัส 🔵 ❤️ ⭐ → `4 3 2` ในโหมดใบงาน
3. ภารกิจ 3 เรียงคำสั่ง ⬆️ ⬅️ ➡️ เพื่อให้หุ่นยนต์ 3D เดินผ่านแผนที่ 3×6 ไปเก็บดาว โดยไม่ชนต้นไม้ หิน หรือสุนัข

มีตัวละครและกระดาน WebGL 3D ด้วย Three.js, ปุ่มนูนแบบ 3D ที่กดแล้วตอบสนอง, แอนิเมชัน, เอฟเฟกต์เสียง และเสียงอ่านภาษาไทย (ขึ้นกับการรองรับของเบราว์เซอร์) หากไม่สามารถโหลด Three.js ผ่าน CDN ได้ จะแสดงกระดาน 2D สำรองที่ยังเล่นได้

- คีย์บอร์ด: ภารกิจ 1–2 กด `1`–`4` เพื่อใส่ตัวเลข, `Backspace` ลบล่าสุด; ภารกิจ 3 กดลูกศร `← → ↑` เพื่อเพิ่มคำสั่ง, `Backspace` ลบล่าสุด
- การแตะตัวเลขหรือลูกศรจะไม่รีเซ็ตฉาก 3D อีกต่อไป
- โหมดผจญภัยสุ่มรหัสและเลือกหนึ่งในสามแผนที่เพิ่มเติม ทุกแผนที่ถูกตรวจแล้วว่าเดินถึงดาวได้
- ถ้าเผลอรีเฟรชในรอบที่บันทึกคะแนน ระบบพยายามกู้คืนภารกิจล่าสุดในแท็บเดิม (`sessionStorage` + API `resume`)

## คะแนน

คะแนนเต็ม **300** (ด่านละ 100): ความถูกต้องสูงสุด 80 คะแนน + เวลาเร็วสุด 20 คะแนน คะแนนถูกคำนวณที่ Supabase Edge Function ฝั่งเซิร์ฟเวอร์ ไม่รับคะแนนที่ส่งมาจากหน้าจอโดยตรง

- ส่งคำตอบผิดลดคะแนนความถูกต้องจนถึงขั้นต่ำ 30
- โบนัสเวลาของแต่ละด่านเริ่มลดหลังเวลามาตรฐานที่กำหนด
- เก็บระยะเวลาและจำนวนครั้งที่ส่งคำตอบผิดแยกตามด่าน
- การรีเฟรชไม่ควรลบผลที่บันทึกไว้บนเซิร์ฟเวอร์
- คะแนนความเร็วเป็นข้อมูลประกอบ ไม่ใช่ข้อสรุปเรื่องความสามารถทางสมองของนักเรียน

## เริ่มทดสอบในเครื่อง

```bash
cd robot-code-adventure
python3 -m http.server 8080
```

เปิด `http://localhost:8080` (ไม่ควรเปิด `index.html` ด้วย `file://` เพราะมี ES modules) จากนั้นกรอกชื่อ/ห้อง เลือกโหมด แล้วเริ่มเกม

หากเชื่อมต่อ Supabase ไม่ได้ จะมีตัวเลือก **ทดลองเล่นโดยไม่บันทึกคะแนน** โหมดทดลองใช้ข้อมูลจำลองภายในเบราว์เซอร์และไม่ได้ส่งข้อมูลนักเรียนขึ้นเซิร์ฟเวอร์

## Supabase

- Project URL: `https://lnmkqcrrpyxjtycttfks.supabase.co`
- Edge Function: `https://lnmkqcrrpyxjtycttfks.supabase.co/functions/v1/game-api`
- Frontend publishable key: `js/config.js` — คีย์นี้ออกแบบให้เปิดเผยในเบราว์เซอร์ได้ **เมื่อจัดสิทธิ์ RLS ถูกต้อง**
- สคริปต์ฐานข้อมูล: `supabase/schema.sql`
- Source ฝั่งเซิร์ฟเวอร์: `supabase/functions/game-api/index.ts`

**ห้ามใส่** รหัสผ่านฐานข้อมูล, Secret key, `service_role` key หรือ personal access token ลงใน GitHub / JavaScript ฝั่งเบราว์เซอร์

ฐานข้อมูลใช้ `game_students`, `game_sessions`, `game_mission_results` และ `game_teacher_access` โดยเปิด RLS และปิดการเข้าถึงตารางโดยตรงจาก `anon` และ `authenticated` — ผ่าน Edge Function ที่ใช้คีย์ฝั่งเซิร์ฟเวอร์เท่านั้น

### คุณครู

เข้าหน้า **สำหรับคุณครู** และใช้บัญชี Supabase Auth ที่ได้รับสิทธิ์ใน `game_teacher_access` แล้ว สามารถดูคะแนนรายด่าน ค้นหา ส่งออก CSV ที่เปิดด้วย Excel ได้ หรือใช้เมนูพิมพ์ของเบราว์เซอร์เพื่อบันทึก PDF

ผู้ดูแลฐานข้อมูลต้องให้สิทธิ์คุณครูหลังสร้างบัญชีใน Supabase Auth เอง เช่น:

```sql
insert into public.game_teacher_access(user_id)
select id from auth.users where email = 'teacher@example.com'
on conflict (user_id) do nothing;
```

> **ข้อจำกัดสำหรับการใช้งานกับเด็กจริง:** ปัจจุบันเด็กกรอกชื่อและห้องเรียนเพื่อเริ่มรอบใหม่ ยังไม่มี roster พร้อม PIN ที่ยืนยันตัวตนรายบุคคล และ API เริ่มเกมยังไม่ได้จำกัดจำนวนรอบ/คำขอตามอุปกรณ์ จึงเหมาะกับการทดสอบหรือกิจกรรมภายใต้การดูแล ไม่ควรใช้เป็นหลักฐานการประเมินที่มีผลสูงหรือเปิดให้บุคคลทั่วไปใช้โดยไม่จัดมาตรการป้องกันเพิ่มเติม ระบบคุณครูต้องได้รับสิทธิ์จริงและไม่ควรให้เด็กเข้าถึงข้อมูลของกันและกัน

## ขั้นตอนก่อนเปิดใช้งานจริง

- ทดสอบ end-to-end บน HTTPS พร้อมเชื่อม Supabase ทั้งการเริ่มเกม บันทึกผล และกลับมาเล่นต่อ
- เพิ่มบัญชีรายชื่อนักเรียน / รหัสส่วนตัวหรือรหัสเข้าชั้นเรียน พร้อมการจำกัดสิทธิ์และอัตราการส่งคำขอ
- พิจารณานโยบายเก็บ/ลบข้อมูลนักเรียน การขออนุญาต และการดูแลข้อมูลเด็ก
- ทดสอบ WebGL และเสียงบนอุปกรณ์ของนักเรียน รวมถึงโหมด 2D สำรอง
